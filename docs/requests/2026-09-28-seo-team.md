## List 1 (grouped by area)

Foundational — Meta & Head Control

• SEO Title field (per page, per language) — separate from the H1/display title.
• Meta Description field — separate from any excerpt/summary field.
• Meta Keywords field (legacy, but some clients still want it visible).
• Canonical URL override, with a sane auto-default so it's never blank.
• Robots meta controls: index/noindex, follow/nofollow, noarchive, nosnippet, max-snippet, max-image-preview — as checkboxes, not raw text.
• Open Graph fields: og:title, og:description, og:image, og:type, og:url, og:site_name — each with its own fallback chain.
• Twitter Card fields: card type, title, description, image.
• Character-count AND pixel-width live preview under title/description fields (Google truncates by pixel width, not character count).
• Auto-fallback logic baked into the render layer: empty SEO title → falls back to H1; empty meta description → falls back to first N characters of body content.
• Site-wide default title suffix/prefix (e.g. "| Brand Name") set once, applied everywhere, overridable per page.
• Google Search Console verification meta tag field (one field, sitewide).
• GA/GTM tracking ID fields (one field, sitewide).
• Custom <head> injection field per page — the escape hatch for anything the UI hasn't caught up to yet.

Foundational — URLs & Structure

• Editable slug field, decoupled from the title (so renaming a page doesn't break its URL).
• Slug uniqueness validation scoped correctly (region/language-aware, not just globally unique — get this wrong at the schema level and you're stuck later).
• Auto-create a 301 redirect from old slug to new slug the moment a slug is changed — never leave that to memory.
• Trailing-slash policy enforced consistently site-wide (with/without, pick one).
• Forced lowercase URLs (case-sensitivity causes silent duplicate-content issues).
• Per-content-type URL patterns (e.g. /blog/%category%/%slug%/ vs /products/%slug%/).
• Breadcrumb auto-generation from the content hierarchy, with manual override.
• Query-parameter indexability rules defined once at the routing layer (which params are real content variants vs. tracking/filter noise) — this alone prevents most of the redirect/crawl-budget mess we just found on your live site.
• Pagination handling decided once (self-canonical vs rel=prev/next) and applied everywhere automatically.

Foundational — Redirects

• 301/302 redirect manager with search/filter, not a flat unsearchable list.
• Bulk import via CSV (essential during migrations).
• Wildcard/regex redirect rule support.
• Redirect-loop detection on save (refuse to save a rule that creates a cycle).
• Auto-suggested redirect when a page is deleted or unpublished, instead of silently 404ing it.

Foundational — robots.txt & Sitemaps

• robots.txt editable inside the CMS, not requiring server file access.
• XML sitemap auto-generated and auto-updated on every publish/unpublish.
• Sitemap auto-splits into an index once it crosses ~50k URLs.
• Per-page "exclude from sitemap" toggle, independent of noindex (sometimes you want a page live and crawlable but not sitemap-promoted).
• Per-content-type default indexability (e.g. internal/utility pages default to noindex unless explicitly overridden).
• Staging/preview environments auto-noindex + auto-blocked in robots.txt by default, with no way to accidentally ship that block to production.

Foundational — Images

• Alt text field required at upload time, with a sitewide "missing alt text" report.
• Automatic image compression on upload.
• Automatic responsive srcset generation.
• Lazy-loading on by default, toggle per image if needed.
• Automatic descriptive file-name sanitization instead of keeping IMG_2931.jpg.
• Image sitemap generation alongside the page sitemap.

Intermediate — Structured Data

• Schema type picker per content type (Product, Article, FAQ, LocalBusiness, Organization, Review, Breadcrumb, HowTo, Event) as a dropdown, never raw JSON-LD paste.
• Auto-population of schema fields from data the page already has (price, SKU, stock status, rating) instead of re-entering it.
• FAQ component that outputs both the visible accordion AND FAQPage schema from the same data entry — one field, two outputs (this is exactly the gap we just closed on your product pages).
• Review/rating field auto-generating Review + AggregateRating schema.
• One sitewide Organization schema block (logo, social profiles, contact info) set once and injected everywhere.
• Pre-publish schema validation against Google's Rich Results requirements, so broken schema never ships.

Intermediate — Internationalization

• Region/language visibility matrix per page (which regions/languages it should appear in) as the actual source of truth.
• Hreflang tags auto-generated from that same matrix — never hand-typed, never able to drift out of sync.
• Region-scoped slug uniqueness (two pages CAN share a slug if their regions don't overlap) — a schema-level decision, painful to retrofit later.
• Explicit fallback-language behavior when a translation is missing, visibly flagged to the editor rather than silently showing blank or English.
• Per-region default currency/unit formatting.

Intermediate — Content Quality Tooling

• Readability score shown while editing.
• Keyword-presence checker: title, first paragraph, headers, meta description.
• Internal link count per page, flagged if zero.
• Word count.
• Sitewide duplicate meta title/description detector.
• Sitewide duplicate/near-duplicate content detector.
• Broken link checker, internal and external, run on a schedule.
• Orphan page report — pages with no internal links pointing to them.
• Content "last updated" timestamp, sortable, so stale pages are easy to find.

Intermediate — Workflow & Ops

• Draft / published / scheduled states for every content type.
• Full revision history with rollback, specifically covering SEO fields (title/description/schema), not just body content.
• Bulk/spreadsheet-style editing view — edit meta titles and descriptions for 50 pages in a grid instead of one page at a time.
• Audit trail: who changed what field, when.
• Optional approval step before an SEO-relevant change goes live (content editor drafts, SEO lead approves).

## List 2 (tiered)

Tier 0 — Non-negotiable basics

Per-page SEO Title + Meta Description fields (with live character-count/truncation warning)
Editable, human-readable URL slugs (not auto-generated IDs)
Canonical URL override per page
Robots meta control per page (index/noindex, follow/nofollow) — separate from the global robots.txt
Open Graph + Twitter Card fields (title, description, image) — with a fallback so you don't have to fill these in for every page
Image alt-text field on every uploaded image, enforced (not optional)
XML sitemap auto-generated and auto-updated on publish
robots.txt editable directly in the CMS, not via server file access
301/302 redirect manager (source → destination, with a search/filter list of existing ones)
Auto-generated breadcrumbs with breadcrumb schema

Tier 1 — Intermediate (this is where most CMSs stop, and where most SEO pain starts)

Structured data templates as dropdowns, not raw JSON-LD — Product, FAQ, Article, LocalBusiness, Review, Organization — auto-populated from the page's own fields
Bulk/spreadsheet view: edit meta titles/descriptions across hundreds of pages in a grid, not one page at a time
Real-time SERP snippet preview (desktop + mobile) as you type the title/description
Hreflang manager with a visual region↔language grid, not manually-typed <link> tags
404 monitor with one-click "turn this into a redirect"
Duplicate meta title/description detector across the whole site
Orphan page detector (pages with zero internal links pointing to them)
Custom <head> injection field as an escape hatch for anything the UI doesn't cover yet (tracking pixels, one-off schema)
Content "last updated" timestamp, visible and sortable

Tier 2 — Advanced (SEO person is now fully self-sufficient, no dev needed)

Google Search Console pulled directly into the CMS — see indexing status, coverage errors, and search performance for a page right next to its edit screen, not in a separate tab
Live structured-data validation against Google's Rich Results API before publish, not after
AI-assisted drafting for meta titles/descriptions/FAQs, grounded in the actual page content (not generic filler)
A/B testing on titles/meta descriptions with CTR impact measured from GSC data
Topic-cluster / pillar-page mapping tool (visualize which pages support which pillar)
Semantic internal-link suggestions ("these 8 pages are relevant to this one and don't link to it")
Core Web Vitals dashly baked in per page/template, not a separate audit tool
Approval/review workflow specifically for SEO fields (a content editor can publish; an SEO lead has to sign off on meta/schema changes)
Version history and rollback scoped to SEO fields specifically
Variant/subset-aware indexability logic — when one "page" has multiple URL variants (sizes, colors, power ratings), the CMS needs first-class support for "which variants are real, independently-indexable pages vs. filters," because get this wrong and you either hide real content or flood Google with near-duplicates. (This is exactly the ?subset= mess we just diagnosed on your project — most CMSs have zero concept of this and it becomes a mess bolted on later.)
